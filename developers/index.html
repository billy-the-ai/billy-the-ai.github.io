Billy Platform

Developers

Your game and your website can read what Billy knows about your server, and Billy can tell them when something happens in it. Two directions, one key.

Get a key Endpoints Event webhooks

Getting a key

Run this in your server. You need Administrator, because a key can read everything below.

/settings api action:Make a new key

Billy stores only a fingerprint of the key, so it is shown once and never again. Lose it and you make another one, which replaces the old one. Keep it on your server — a key shipped inside a game client is a key everybody has.

Add allow_posting:true if you also want the key to post messages. Leave it off if you only need to read; you can always make a new key later.

Sending it

curl https://billyserverai.duckdns.org/api/v1/server \
  -H "Authorization: Bearer billy_your_key_here"

There is no server id anywhere in these paths. The key says which server you are asking about, so a key can only ever read the one server it was made in.

Endpoints

Everything answers JSON. Sixty requests a minute per key.

  • Get
    /api/v1/server

    Name, member count, the plan this server is on, and when it was created.

  • Get
    /api/v1/members/{user_id}

    Messages, level and progress, Helper, Marketing and Scouting points, roles, and when they joined. Someone who has left still has a record.

  • Get
    /api/v1/leaderboard/{kind}

    helper, marketing, scouting or messages. Takes ?limit=, up to 50.

  • Get
    /api/v1/tickets

    How many tickets are open and closed, and the count for every status you use.

  • Get
    /api/v1/cases

    Recent moderation cases, newest first: number, action, who, which moderator, and the reason. Takes ?limit=, up to 100.

  • Post
    /api/v1/say

    Post a message to a channel, as Billy. Needs a key made with posting allowed. Body: {"channel_id": "…", "content": "…"}. Mentions never ping — a machine cannot @everyone your server — and every post is written to your audit trail.

What an answer looks like

{
  "ok": true,
  "member": {
    "id": "204…",
    "in_server": true,
    "name": "Ricky",
    "joined_at": "2025-05-01T00:00:00+00:00",
    "roles": [{ "id": "998…", "name": "Helper" }],
    "messages": 1204,
    "level": 7,
    "progress": 54,
    "needed": 210,
    "points": { "helper": 12, "marketing": 3, "scouting": 0 }
  }
}

Failures answer with {"ok": false, "error": "…"} and a normal status code: 401 for a key that is not valid, 403 for something the key is not allowed to do, 404 for something that is not there, 429 when you are going too fast.

Event webhooks

The other direction. Billy POSTs to a URL you own when something happens in your server.

/settings webhook action:Set the URL url:https://api.yourgame.com/billy events:case.created,member.joined

case.created

A moderation case got its number. Sends the case, the action, who it was about and which moderator.

ticket.closed

Support finished with someone. Sends the ticket, its type, who opened it and who closed it.

helper.clip

Billy caught a member helping another member. Sends both people and a link to the conversation.

member.joined

Somebody arrived. Sends who, when their account was made, and the new member count.

Checking a delivery is really Billy

Every request carries an HMAC of the exact body, made with the signing secret you were shown when you set the URL. Compare it before you trust anything in the payload.

X-Billy-Event: case.created
X-Billy-Delivery: 9f2c1a7b4e0d3a58
X-Billy-Signature: sha256=<hmac of the raw body>

# Python
import hmac, hashlib
expected = "sha256=" + hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
if not hmac.compare_digest(expected, request.headers["X-Billy-Signature"]):
    abort(401)

The rules Billy keeps

  • The URL has to be https, on a public host. Addresses inside a private network are refused, on purpose.
  • An event says what happened and who it involved. Message content, ticket transcripts and the reasons moderators type are never sent — ask for those with your key, where your server had to authenticate.
  • A URL that fails twenty times in a row is switched off. /settings webhook shows you the last response Billy got.
  • Billy does not retry a delivery, and does not wait for your endpoint. Your server being down never slows a ban down.
